## How it works

The design is written in [DSLX](https://google.github.io/xls/dslx_reference/) and compiled to
SystemVerilog with [google/xls](https://github.com/google/xls). No Verilog is written by hand for
the core: `diff_engine.x` is converted to IR, optimised, and code-generated by the XLS toolchain,
and only a thin wrapper (`wrapper.sv`) connects the result to the Tiny Tapeout pins.

The DSLX top level is a *proc* named `Top`. A proc communicates over channels rather than ports, so
XLS gives the generated module a ready/valid handshake on each channel. Because the Tiny Tapeout
pins are continuously driven rather than streamed, the wrapper ties `valid` and `ready` high, which
makes the core advance once per clock and lets synthesis fold the handshake logic away entirely.

The current core is a placeholder: it drives a constant on the dedicated outputs while the
signal-processing pipeline is being built up. The bidirectional pins are unused and configured as
inputs (`uio_oe = 0`).

## How to test

Apply any values to the dedicated inputs `ui_in[7:0]` and read the dedicated outputs `uo_out[7:0]`.

The placeholder core ignores its inputs and drives a fixed pattern on `uo_out`, so the test is
simply that the outputs settle to that constant value once the design is selected and released from
reset. The bidirectional pins can be left unconnected.

The same sources also build for an Arty A7-35 FPGA (see `fpga/xc7/`), where two push buttons drive
`ui_in[7:6]` and two LEDs show `uo_out[7:6]`, which is a convenient way to exercise the design
before committing it to silicon.

## External hardware

None. The design needs no external hardware beyond the Tiny Tapeout board itself.
